# Errand

A chat agent that books, reschedules and cancels home-service errands against a mocked provider, and never
double-books, never acts without approval, and never takes instructions from a provider review.

**The model parses, code decides.** The LLM turns a message into a typed intent; a deterministic workflow owns
state, and every write passes an approval gate, an outbox and a status check. Pure Python 3.11+ standard
library: nothing to install.

## Run it (three commands)

```bash
make test     # unit tests, negative controls, fuzz, intent eval, 35 scenarios -> reports/
make demo     # web console with streaming chat and live trace: http://127.0.0.1:8765
make chat     # the same agent in the terminal
```

No `make` (Windows): `python -m unittest discover -s tests -t . && python -m evals.run`, then
`python -m errand serve`. Optional live model: set `ANTHROPIC_API_KEY` (and optionally `ERRAND_MODEL`, default
`claude-haiku-5-5`). Without a key the offline rule model is used; tests never call a network.

## Is the model understanding people? (interpreter eval)

The scenarios prove the system is safe whatever the model does. A separate eval measures how well the
interpreter understands real phrasing: 142 labelled utterances grounded in public datasets (SGD, Taskmaster-1,
CLINC150, Hinglish-TOP) plus handwritten Hinglish, synthetic and adversarial rows, split into dev and held-out
test. Sources, method and licences: [`evals/data/SOURCES.md`](evals/data/SOURCES.md). Report:
[`reports/intent_eval.md`](reports/intent_eval.md).

| Rule model | Before (baseline) | After dev-driven fixes |
| --- | --- | --- |
| Strict accuracy, all | 45.1% | 99.3% |
| Strict accuracy, held-out test | 42.6% | 98.5% |
| Strict accuracy, Hinglish | 33.3% | 100% |
| Confirm false positives (safety) | 4 | 0 |
| Out-of-scope requests turned into actions | 40.6% | 0% |

The safety gates (zero confirm false positives, at most 5% out-of-scope actions, at least 95% held-out accuracy)
run in `make test`. To measure Claude: `ANTHROPIC_API_KEY=… make intent-eval MODEL=claude RECORD=1` records its
outputs to `evals/fixtures/claude/`; `make intent-eval MODEL=recorded` then replays them offline.

**Hinglish.** The agent understands Hindi-English code-mixed requests ("kal subah plumber chahiye Indiranagar
mein, 1500 se kam", "pehla wala", "haan book kar do"), in both the rule model and the Claude prompt. Replies stay
in English so that the approval text (provider, slot, price) is unambiguous; localized reply templates are the
natural next step.

## Readings of the brief's ambiguities

- `hold_slot` needs no approval: it is reversible and reveals the real price. Approval names the quoted price.
- Reschedule and cancel approvals name the booking's price. Holds are not part of the reschedule contract.
- Book keys are `sha256(approval, hold)`, so a re-hold after a verified non-booking gets a fresh key;
  cancel and reschedule keys are per approval. Every retry of one approved action reuses its key.
- "First cancel call fails with 503" means first call per booking, per provider instance.
- Required: service, area, date. Time and budget are asked once; "no preference" counts as an answer.
- An over-budget quote is shown and flagged but can still be approved explicitly.
- "This week" and weekday names resolve against the injected clock in Asia/Kolkata.
- Several matching bookings for "my AC servicing" means asking which, never guessing.
- A repeated "yes" after success restates the existing booking and sends nothing.
- Nice-to-have: none built. The time went into the must-haves, fault injection and the fuzz.

## Limits and next steps

- The Claude adapter is implemented but not exercised by the test suite, which must stay offline. Next: record
  a session with `RecordedModel(mode="record")` and replay it as fixtures in CI.
- The rule model understands the brief's phrasings and common variants, not open-ended language; that is the
  live model's job.
- Holds have no release call in the contract, so abandoned holds lapse after 10 minutes.
- Proactive follow-up (provider cancels, agent rebooks with approval) is the natural next feature: it reuses the
  hold, approval and outbox paths unchanged.
