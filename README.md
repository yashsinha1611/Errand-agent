# Errand

A chat agent that books, reschedules and cancels home-service errands against a mocked provider, and never
double-books, never acts without approval, and never takes instructions from a provider review.

**The model parses, code decides.** The LLM turns a message into a typed intent; a deterministic workflow owns
state, and every write passes an approval gate, an outbox and a status check. Pure Python 3.11+ standard
library: nothing to install.

## Run it (three commands)

```bash
make test     # unit tests, golden-set integrity, fuzz, intent eval, 42 scenarios -> reports/
make demo     # web console with streaming chat and live trace: http://127.0.0.1:8765
make chat     # the same agent in the terminal
```

Without `make` (Windows): `python -m unittest discover -s tests -t .` and `python -m evals.run` for the tests,
`python -m errand serve` for the console, `python -m errand chat` for the terminal.

Python 3.11+ only; nothing to install. **Step-by-step guide, including how to use the console and the terminal
chat, Windows, Claude and troubleshooting: [`docs/RUNNING.md`](docs/RUNNING.md).** To use Claude, put `ANTHROPIC_API_KEY=…` in a `.env` file (git-ignored)
or export it; without a key the offline rule model is used, and tests never call a network. To put it online
on AWS (Lightsail or EC2, HTTPS and a password in front, one setup script): [`docs/DEPLOY_AWS.md`](docs/DEPLOY_AWS.md).
To test every feature and guardrail with Claude (`make check-llm`, `make live-scenarios`, and a hands-on script):
[`docs/TESTING.md`](docs/TESTING.md).

### Scenarios on a recorded model

The brief asks for evals against "a scripted or recorded model". `make test` runs every scenario against the
deterministic offline interpreter plus scripted models that misbehave on purpose. `make evals-recorded` runs the
same 42 scenarios against **Claude's real outputs**, recorded locally once with a key (`make record-scenarios`, a few
cents) into the git-ignored `evals/data/recordings/scenarios/`. Recordings are not included in this repository.
Replay never touches the network, and it is strict: a prompt
missing from the recording (because the prompt or a scenario changed) marks that scenario STALE instead of
letting another model answer. `RecordedReplayTest` checks record, offline replay and stale detection.

## Is the model understanding people? (golden set and interpreter eval)

The scenarios prove the system is safe whatever the model does. A separate, versioned golden set measures how
well the interpreter understands real phrasing. Golden **v1** is frozen with SHA-256 checksums; every eval run
verifies them first, so an edited golden file fails loudly. Changes ship as a new version with a release note.

| Suite | Rows | What it is | Gate | Rule model | Claude Haiku 5.5 (2026-10-31) |
| --- | --- | --- | --- | --- | --- |
| regression | 130 | Everyday phrasing grounded in SGD, Taskmaster-1, CLINC150 and Hinglish-TOP, plus handwritten Hinglish and two-step synthetic rows | test-split strict ≥ 95%, Hinglish ≥ 95%, out-of-scope actions ≤ 5% | 100% | 96.2% strict overall; 98.4% test split |
| adversarial | 12 | Confirm traps and user-side injections, kept separate so accuracy can't hide a safety failure | zero false confirmations | 91.7%, 0 false confirmations | 100%, 0 false confirmations |
| capability | 42 | Harder phrasing: voice-style rambles, abbreviations, corrections, emoji, two requests, Devanagari, Kannada-English | tracked, not gated | 45.2% (headroom) | 95.2% |

Live end-to-end checks: **41/42** scenarios passed in the latest one-trial run (zero invalid fallbacks; S21
missed its expected options in this run). The 79 hard probes scored **77/79**, with **zero safety failures**.
See the [live scenario report](reports/live/scenarios_claude-haiku-5-5.md) and
[hard-probe report](reports/live/hard_probes_claude-haiku-5-5.md). These are single-run live-model results;
the full intent breakdown is in [`reports/intent_eval.md`](reports/intent_eval.md).

Baseline before the dev-driven parser fixes: 45% strict accuracy, 4 false confirmations, 41% of out-of-scope
requests turned into actions. Release note: [`evals/data/golden/v1/RELEASE.md`](evals/data/golden/v1/RELEASE.md);
provenance and licences: [`evals/data/SOURCES.md`](evals/data/SOURCES.md); report:
[`reports/intent_eval.md`](reports/intent_eval.md).

**Second labeller.** `make review-sheet` writes `review_sheet.csv`; the guide is
[`evals/data/golden/v1/REVIEW.md`](evals/data/golden/v1/REVIEW.md). `make agreement` then reports raw agreement,
Cohen's kappa and the rows to adjudicate.

**Live model.** `ANTHROPIC_API_KEY=… make intent-eval MODEL=claude RECORD=1` scores Claude on all three suites and
stores outputs locally under the git-ignored `evals/fixtures/claude/`; `make intent-eval MODEL=recorded` replays
them offline on that machine.

**Hinglish.** The agent understands Hindi-English code-mixed requests ("kal subah plumber chahiye Indiranagar
mein, 1500 se kam", "pehla wala", "haan book kar do"), in both the rule model and the Claude prompt. Replies stay
in English so that the approval text (provider, slot, price) is unambiguous; localized reply templates are the
natural next step.

## Readings of the brief's ambiguities

- `hold_slot` needs no approval: it is reversible and reveals the real price. Approval names the quoted price.
- Reschedule and cancel approvals name the booking's price. Holds are not part of the reschedule contract.
- Book keys are `sha256(approval, hold)`, so a re-hold after a verified non-booking gets a fresh key;
  cancel and reschedule keys are per approval. Every retry of one approved action reuses its key.
- "First cancel call fails with 503" means first call per booking, per provider instance.
- Required: service, area, date. Time and budget are asked once; "no preference" counts as an answer.
- An over-budget quote is shown and flagged but can still be approved explicitly.
- "This week" and weekday names resolve against the injected clock in Asia/Kolkata.
- Several matching bookings for "my AC servicing" means asking which, never guessing.
- A repeated "yes" after success restates the existing booking and sends nothing.
- Nice-to-have: none built. The time went into the must-haves, fault injection and the fuzz.

## Limits and next steps

- The test suite stays offline. `make record-scenarios` can capture Claude's outputs locally, and
  `make evals-recorded` replays them without a key. Generated recordings are git-ignored and are not included.
- The rule model understands the brief's phrasings and common variants, not open-ended language; that is the
  live model's job.
- Holds have no release call in the contract, so abandoned holds lapse after 10 minutes.
- Proactive follow-up (provider cancels, agent rebooks with approval) is the natural next feature: it reuses the
  hold, approval and outbox paths unchanged.
